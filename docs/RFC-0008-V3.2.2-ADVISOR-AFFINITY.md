# RFC-0008 — MARTCOM AI V3.2.2 Advisor Affinity

## Objetivo
Garantizar que el asesor con cuyo nombre se presenta MARTCOM AI sea el mismo usuario real de Chatwoot que recibe el handoff.

## Regla principal
La selección del asesor ocurre al inicio de la conversación, no al momento del handoff.

```text
Nueva conversación
  ↓
Resolver turno (weekday / saturday / sunday)
  ↓
Reservar siguiente asesor real
  ↓
Guardar advisor_affinity en memoria
  ↓
Usar ese nombre en la presentación IA
  ↓
Diagnóstico
  ↓
Resumen
  ↓
Handoff al mismo assignee_id
```

## Memoria
```json
{
  "advisor_affinity": {
    "agent_id": 32,
    "agent_name": "Vicente Martinez",
    "group": "weekday",
    "rotation_position": 6,
    "total_agents": 6,
    "reserved_at": "...",
    "status": "reserved"
  }
}
```

Al completar el handoff, `status` pasa a `assigned`.

## Persistencia
La reserva se almacena también en `HANDOFF_ROTATION_FILE`, por lo que un reinicio no debe cambiar el asesor reservado.

## Rotación
La rotación avanza al reservar una conversación. Un fallo posterior de Chatwoot NO cambia el asesor de esa conversación: los reintentos se realizan al mismo ID reservado.

## Compatibilidad
- `AI_INTRO_AGENTS` queda como fallback de compatibilidad únicamente si no existe un turno real configurado.
- Conversaciones antiguas conservan el nombre con el que ya se presentó la IA.
- Si un nombre antiguo coincide de forma segura con un asesor real del turno, se crea una afinidad heredada sin cambiar el historial visible.

## Inspector
Se muestran:
- Asesor reservado.
- ID reservado.
- Presentación IA.
- Asesor del handoff.
- ID del handoff.
- Coincidencia de identidad.
- Fecha/hora de reserva.
- Posición de rotación.

## Eventos
- `advisor_affinity_reserved`
- `advisor_affinity_legacy_matched`
- `advisor_affinity_skipped`
- `advisor_affinity_fallback_intro`

## Rollback
Volver a V3.2.1. Los nuevos campos de memoria son opcionales y V3.2.1 los ignorará.
